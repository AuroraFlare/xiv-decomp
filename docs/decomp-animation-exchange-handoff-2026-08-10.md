## Corrected conclusions

### Guildleve transformations

The six implemented transformation scripts formerly used `0x04000000`, but
packed-value decoding proves that it selects category 4,
`cmn/lib/base/0000`, low value 0. None of the 18 relevant assets has that bank.
Their exact `cbbm_activ` and `cbbm_deact` MTB/MCB/CIBT resources live in
`emp_emp/bid/base/0000`.

Installed-executable evidence closes the activation bridge: opcode `0x0134`,
PASSIVE state 0 to ACTIVE state 2, enters phase 4 and waits for/checks
`cbbm_activ`, falling back to `cbbm_id0`. The reverse bridge is also exact:
ACTIVE state 2 to PASSIVE state 0 enters phase 5, enqueues transition ID `0x1E`,
and maps it through the native motion table to `cbbm_deact`. Actor flag `0x40`
selects the `cbbp_u_activ`/`cbbp_u_deact` upper-body lane instead. The six bad
packed animation sends have therefore been removed; activation/deactivation are
client-native state transitions. The later animation-controller vtable call
selects bank 1 (`bid/0001`) on activation or bank 0 (`cmn/fid`) on
deactivation; that selector is separate from the earlier transition-motion
mapping. The atlas locks the executable hash,
native addresses/bytes, all three exact CIBT transition profiles, and the four
nonstandard `c005` MTB headers. Exact reveal ordering still needs a
presentation-safe live test because inherited hate can publish ACTIVE before
the intended reveal moment. Fourteen of the 20 source-backed leves still lack
local encounter scripts; their source identities are exact, but recovered Lua
and ID-tagged coordinate probes contain no authoritative retail placement or
choreography rows, so no guessed scripts were added.
