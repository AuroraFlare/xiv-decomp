## 1) 110016 – Forever Taken (Man304, Lv34)

### Summary

- Core quest logic is fully playable and sequence-complete.
- Client has complete text/script payload, but not every optional ambient line is wired into server-talk routes.
- Required narrative path includes:  
  - `man30400` intro/soil-collection setup  
  - `man30410` return + counter clear closure  
  - `man30420` private Waking Sands assembly  
  - `man30430` companion conclusion  
- Reward is present in server data.

### Gameplay state map

1. **Prereq chain**
   - This quest is level 34 MSQ entry point after `110015` (“Toll of the Warden”).
2. **Start node**
   - Player talks to Hedyn in Ashcrown Consortium.
   - `man30400` starts and begins the Crystal objective.
3. **Item objective**
   - Requires 5 unstackable “Unaspected Crystal” interactions on separate soil markers near Silvertear Falls.
   - Implementation uses a per-quest counter for progress, not stacked item count.
4. **Per-marker dedupe**
   - Each marker has its own persistent completion flag to prevent duplicate credit.
5. **Return + completion**
   - Returning to Hedyn after five burials triggers dialog row `306` and `man30410`.
   - Counter is cleared after handoff, then objective resolves.
6. **Instance transition**
   - Returning to Waking Sands main hall transitions into the private area instance for the Path assembly scene.
   - `man30420` runs with Garlean, beast tribe, and Echo-danger exposition.
7. **Companion branch**
- Companion is dynamically spawned server-side.
- Path companion lines are selected from 9 personality variants (two lines at this point).
8. **Wrap scene**
   - `man30430` runs (companion + Minfilia conclusion).
9. **Completion**
   - Quest rewards + public area return.

- `man30410`

- Implemented as an instance quest (not just dialogue).
- Uses scripted event sequencing through escort/rush + fight phases with direct cinematic handoff into combat.
- Uses a “replay-safe” structure: route/fight setup can be retried when players re-enter/deserialize into content flow.

### Observed implementation pattern

From script + director, the flow resolves around:

1. **Entry + state read**
   - `main(...)` checks active quest owner, mission phase, and elapsed timers.
2. **Pacing**
- Landing/readiness gating before progression into cinematic and combat steps.
3. **Scene-driven phase transitions**
   - A first phase event primes the scripted pre-fight beat.
4. **Combat phase**
- The server-side director enters the intended battle population and tracks outcomes for objective completion.
5. **Post-fight closure**
- Returns through Tataru-directed closure path and marks sequence completion.

### Failure and recovery behavior

- Instance timeout is enforced.
- Leave-area/owner-loss checks are present in director logic.
- Failure paths generally rollback and warp players out with state cleanup.

## 4) 110019 – Futures Perfect (Man406, Lv46)

### Summary

- Implemented as a fully scripted instance with three major runtime phases:
  - pursuit phase
  - combat phase
  - cave aftermath phase
- Director logic is robust and explicit about player readiness, timeout, and cleanup.

### Quest / director details

- File-level constants:
  - `QUEST_ID = 110019`
  - timeout: `45 * 60` seconds
  - landing delay: `3` seconds
  - event timeout: `8` seconds
  - fight level: `50`
  - notice events:
    - `imperialsWithdraw` (opening/pursuit start)
    - `imperialsCornered` (combat start)
    - `battleWon` (completion / cave resolution)
- Combatants are explicit and data-driven:
  - Imperial juggernaut, centurion, hoplomachus, sagittarius
  - each with classId, bnpcId, uniqueId, hp, and positional data
- Cave aftermath actor set is explicit:
  - 5 frightened children + one cave trigger actor
- Quest flags and local state:
  - `MAN406_FLAG_PURSUIT_COMPLETE`
  - local `completed`, `failed`, `routeStarted`, `combatStarted`, `caveReady`, plus elapsed timers.

### Detailed phase flow

1. **onCreateContentArea**
   - Director registers actor members from content players into the content group.
2. **Start loop (`main`)**
   - Polls owner/quest state each second.
   - As long as sequence is active and player remains in private battlefield, it advances phase timers.
3. **Opening phase**
   - Once landed + delay satisfied in `SEQ_015`, event `imperialsWithdraw` is fired.
   - `beginOpening` delegates event `processEvent020`, ends the dialog, then starts pursuit route.
4. **Pursuit phase**
   - Escort director created from `futures_perfect_imperial_pursuit`.
   - Route markers, leash settings, and presentation delegation are configured.
   - Completion/failure of escort is checked every tick.
5. **Arrival -> combat transition**
   - On route complete OR explicit quest flag, fires `imperialsCornered`.
   - `beginCombat` sets pursuit flag complete, updates ENPCs, ends event, despawns/cleans old spawns, spawns four combatants, and starts content group.
   - Combatants are configured with:
     - level 50
     - aggression, detection, ranged position hold (for sagittarus), vitality sync, default MP fallback
     - explicit HP and encounter settings
6. **Kill detection**
   - `countDefeated` tracks alive/dead by uniqueId across COMBATANTS and increments state when dead/missing.
7. **Completion transition**
   - On all four defeated: `battleWon` is queued.
   - `completeBattlefield` marks completed, clears combatants, delegates `pE30`, sets `SEQ_020`, spawns cave actors, then moves all entrants into cave coordinates.
8. **Landing recovery path**
   - If player lands while already in `SEQ_020` and cave entities were not spawned yet, server recreates cave actors and teleports in.
9. **Talk event wiring (aftermath)**
   - 5 child class IDs mapped to process events:
     - 1000957 -> `processEvent045_1`
     - 1000958 -> `processEvent045_2`
     - 1000959 -> `processEvent045_3`
     - 1000960 -> `processEvent045_4`
     - 1000961 -> `processEvent045_5`

### Fail/cleanup behavior

- Fail reasons:
  - missing quest
  - pursuit/map spawn failures
  - owner defeat
  - route failure
  - timeout
  - leaving battlefield
  - cave aftermath spawn failure
- On fail:
  - stop pursuit director
  - despawn combatants
  - call `ContentFinished`
  - warp participants back to public Waking Sands entry points
- This prevents stranded or stuck participants.

### Rewards

- 138,000 gil
- 46,000 EXP
