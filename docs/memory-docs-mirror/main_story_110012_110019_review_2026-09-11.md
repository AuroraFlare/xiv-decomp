  selection event once; suppress the delayed linkpearl message if the quest has

  command already prepends sequence as argument 1; the callback previously

  English journal expression (CSV column 15), selects entries 220/221 using
  `$E4($E8(3),1)`. Updated the older validator that asserted the incorrect layout.

  has a final return-to-Tataru journal entry at 15 and none at the old recovery
  sequence 20. A separate saved flag preserves the existing cutscene checkpoint
  behavior. Old sequence-20 saves migrate when speaking to Tataru. Both failed
  hand-ins and retries still execute the warp needed to release the scene fade.

## Follow-up review

The additional transition/recovery pass found one further gap in Fade to White:
sequence 25 is saved before a 60-second Lua wait, but a server restart loses the
waiting callback before it posts the linkpearl message. Tataru now restores the
message if none is pending. The delayed callback also checks for a pending
message, preventing a duplicate if Tataru was used while the timer survived.
Runtime regressions cover the saved waiting stage, repeated Tataru interactions,
and a timer completing after recovery. The compiled suite and all eight Python
validators above pass after this fix.

Checked Man200 `pE25` against its original bytecode: the apparent second `ask`
in the decompiled source is not present. It returns the original choice from
register R8, so the existing acceptance-only warp is correct. No other confirmed
progression issue was found in this follow-up pass; in-game verification remains
outside these checks.

The next cancellation/entry-failure review confirmed a separate Man200 naming
bug. `RetainerNamingWidget.getAskResult` returns numeric `-3` for cancellation
(verified against its original Lua 5.1 bytecode). `pEN` forwards that widget
result, while the server previously accepted every non-nil result as a name.
It now requires a nonempty string. Successful naming updates the duty flag,
refreshes reward NPC state, and saves before the return transfer; cancellation
does none of those things. A regression invoking the recovered widget result
failed on the previous handler and passes after the fix. It also covers nil,
false, empty names, and valid naming with saved progress before transfer. The
compiled starter-city/main-story suite passes after the final change.
