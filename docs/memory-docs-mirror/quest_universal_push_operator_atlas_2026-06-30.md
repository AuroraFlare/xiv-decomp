## Event Transport Map

The local server does not have literal `requestEvent`, `getEventResult`, or `finishEvent` symbols. The operational mapping is:

| Retail concept | Local surface | Why it matters |
| --- | --- | --- |
| request/start | `KickEventPacket` plus client `EventStart` | Establishes the real owner actor, event name, and event type. |
| push/function | `RunEventFunctionPacket` / `callClientFunction` | Sends `delegateEvent`, cutscene wrappers, widget calls, and director methods. |
| result/selection | client `EventUpdate` | Resumes Lua and carries cutscene branch/selection/cancel results. |
| finish | `EndEventPacket` / `player:EndEvent()` | Must be delayed correctly for after-warp and multi-update cutscenes. |
| active route | `Player.currentEventOwner/currentEventName/currentEventType` | `RunEventFunction` uses this state, so calls after close lose routing. |

Probe logs must capture typed Lua params, not only unwrapped values, because SNPC tuple rows and branch rows depend on exact payload shape.

## Safety Rule

Do not pair recovered scaffold cutscenes with `AcceptQuest`, `CompleteQuest`, item grants, EXP, or `EndEvent` changes until route/order is proven. Scene keys can render and still be wrong. The winning proof is: live owner, event type, wrapper method, typed args, cutscene result, sequence/flags before and after, and correct close timing.
