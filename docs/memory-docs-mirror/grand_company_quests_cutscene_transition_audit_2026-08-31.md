## Scope and source order

This audit covers all 69 named Grand Company quests in the `patch_1_18` through `patch_1_23` availability blocks. The client scenario Lua is the authority for event method names, dialogue ownership, cutscene keys, fade ownership, and event arguments. The client journal tables are the authority for objective order. The local Elemen ledger supplies rewards where the client reward row does not contain EXP. Server implementations are assessed last.

## Third-pass argument, salute, and scaffold audit (2026-09-01)

The follow-up signature inventory found 167 recovered `processEvent*` methods with one or more parameters beyond player, quest, and actor. All 47 literal direct-script dispatches now pass exactly the recovered arity. In particular, the three familiar pre-fight events explicitly pass `false` to select their authored after-warp fade branch, the dialogue/join closers carry their unused client slots, and `Com0l6.processEventGUINCUMStart(1)` selects the prerequisite-aware “as you know” dialogue. Toto-Rak entry/completion calls are now variant-sized instead of sending a copied argument tuple to all three client classes.

The standard quest emote path is also complete in the server: an emote-enabled `QuestENpc` publishes the actor status, the client returns the quest-specific trigger name through `PopulaceStandard`, and `Quest.OnEmote` passes it to Lua. Existing multi-emote quests establish that these `emoteDefaultN` names are client-authored condition slots rather than arbitrary server guesses. Both promotion families have exactly one company-salute slot, `emoteDefault1`.

Consequently, `G*701` sequence 50 and `G*702` sequence 20 now keep officer reminder talk available while enabling the emote condition. Only `emoteDefault1`, on the correct officer and sequence, can call the guarded promotion transaction and its recovered completion method (`17→21` or `27→31`). Ordinary officer talk cannot change rank, consume the medal, pay the rank-31 reward, or complete the quest.

Finally, the shared generic template is now explicitly non-executable: `GENERIC_ROUTE_AUDIT_GATE` returns before synthetic sequence, kill, seal, EXP/gil, or completion logic. It remains useful as the 48-route journal/event/reward inventory, but changing the broad Grand Company switch cannot turn the old officer-only scaffold into gameplay. Dedicated route owners do not use that sequencer. All 69 named offers remain disabled pending live verification.

The fourth pass also traced the offer state itself. `QuestStateManager` creates an available quest at `SEQ_ACCEPT` (`65535`), and only an NPC published from that state can route the recovered acceptance dialogue into `player:AcceptQuest`. Twenty-four bespoke owners previously began at sequence zero only: the twelve direct `Com0[lgu]1`–`4` routes, the three Toto-Rak routes, the three Dzemael routes, and the six campaign audit routes. Those owners now distinguish the offer interaction from an already-active sequence-zero retry. All 36 bespoke routes have an explicit `SEQ_ACCEPT` plus guarded `AcceptQuest` contract; the 33 unresolved generic wrappers intentionally have neither. This changes no availability entry.
