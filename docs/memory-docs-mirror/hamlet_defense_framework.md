# Hamlet Defense Framework

This implementation seeds the server-side framework for Hamlet Defense using the archived Gamer Escape overview, the Console Games Wiki summary, screenshots, and local mined achievement/message data.

Implemented:

- Three hamlets: Aleport, Hyrstmill, and the Golden Bazaar.
- Retail captain and quartermaster names for the three hamlets, plus the known level 45-50, full-party and 30-minute rules. The old supply-rating-2 value is retained only as a database-failure fallback; normal battles snapshot the live campaign rating.
- Captain events now use the recovered actor-driven text dispatcher: `1500340` selects Aleport, `1500342` selects Hyrstmill, and `1500341` selects Golden Bazaar. The former local stub incorrectly called `getAleportText` for all three captains.
- Test anchors now use local event NPC spawn rows: Aleport zone 129 near Rhotblaet/B'davzzi, Hyrstmill zone 152 near Rontremont/Dhebi Polaali, and Golden Bazaar zone 171 near Carmine/P'lhabgo.
- Spawned city-specific militia formations recovered from the actor tables: ten archers across three defense lines plus smith, outfitter, cook, and barber support militia; four Hamlet supply-cache actors; timed beastman waves; and a leader wave.
- Special non-beastman waves from the score data: frightened fauna, beasts of burden, and the dedicated Errant Soul actor for each hamlet. Errant Soul is now held behind the preserved retail gate: every non-leader beastman must be dead, and both earlier unique foes must have been slain by militia archers.
- Enemies immediately acquire hate on supply carts or militia so the defense fight starts without needing player proximity aggro.
- "Duty Commenced" start messaging, including a `worldMaster` `50011` bound-by-duty attention probe, plus captain start/victory/failure lines, gate breach, defense-line breach, cart raid, leader arrival, leader order, and support-effect messages based on `InstanceRaidHamletDefense.csv`.
- Guildleve-style HUD counters for carts remaining, beastmen defeated, and a compact score meter.
- Retail-lifecycle test path: `!testhamlet retailstart hyrstmill` now stays in public Hyrstmill, attaches a Hamlet director using the guildleve-compatible client class path with selectable init profiles, kicks the intro `noticeEvent`, tries the selected cutscene experiment mode, sends a delayed Hamlet HUD bootstrap after duty start, and has a 15-second auto-commence fallback if the client never returns from the intro event. The old private-content-area probe is now `!testhamlet retailinstance hyrstmill` and is unsafe because it can crash the stock client.
- Hamlet PushEvent probe path: `!testhamlet pushprobe <hamlet-or-actorClassId>` spawns a `/Chara/Npc/Populace/PopulaceHamletPushEvent` actor with a temporary push/talk/notice event set; `!testhamlet pushnotice <hamlet-or-actorClassId>` also kicks that actor's `noticeEvent`. When the client returns `EventStart`, `PopulaceHamletPushEvent.lua` logs the actor/event context, ends the probe event, and starts the public retail lifecycle after a short delay. Live testing on 2026-05-29 proved that `1500437` can fire through `pushDefault` without crashing, but it still leaves the stock client in the `Official Behest`/guildleve HUD family, so the PushEvent actor is not sufficient by itself to open the Hamlet widget.
- DoL pot effects after three delivered pots: `rrr` attack down, `bbb` HP down, `ggg` sleep, mixed red/blue/green enmity/order reset. The GM command also accepts these shortcuts directly.
- DoH instrument effects: spiked militia archer attack, blessed laborer regen, reinforced defense/evasion for militia personnel, musked order/enmity reset.
- Leader orders periodically redirect enemy focus while the leader is alive; musked/rainbow support counts prevented orders.
- Requested-item delivery through the three militia quartermasters, with server-validated inventory removal, recovered NQ/HQ values (1,000/10,000 points and 4/6 anima), persistent 50-hour supply plus 25-hour defense cycles, stockpile ratings, and deterministic top-20 rankings. Materia-enhanced equipment delivery remains disabled until its point/anima formula is recovered.
- Score categories covering the recovered sheet values for battle actions plus a battle-start party snapshot for discipline/class/job-crystal composition, per-crafter/gatherer counts, live top-20 provisioner presence, and the 500-point no-KO result. Rank-2 campaigns apply the archived x2 final-score correction.
- Victory spawns a five-minute party-shared coffer using the recovered Bronze/Silver/Gold/Highest score bands and each hamlet's item pool. Top-20 provisioners claim their separate pool by speaking to the correct militia captain during that same five-minute window, and ranks 1-3 also receive a seal/beast-currency roll. The 60,000-point tier currently guarantees the first city militia head based on player reports; other selection is uniform because exact retail item weights are unpublished.
- Private Hamlet tests now replace their construction shell with the real Hamlet director, spawn the correct city captain inside the result instance for provisioner claims, and return participants to their saved public-area positions when the five-minute result window closes. Failure keeps the same five-minute inspection window before returning the party.
- Exact recovered result text IDs and labels are cataloged in `docs/hamlet_defense_point_rules.md`.
- Achievement hooks for leader kills, first-blood score thresholds, per-hamlet win progress, and all-hamlets victory.
- GM test command: `!testhamlet hyrstmill`, `!testhamlet aleport`, `!testhamlet goldenbazaar`, `!testhamlet retailstart hyrstmill`, `!testhamlet retailtutorial hyrstmill`, `!testhamlet retailinstance hyrstmill` (unsafe), `!testhamlet widgetprofile loadbare|loadwindow|bare|window|loadbareopen|loadwindowopen|bareopen|windowopen`, `!testhamlet uistatus`, `!testhamlet cleanup`, `!testhamlet commence`, `!testhamlet win`, `!testhamlet fail`, `!testhamlet land red`, `!testhamlet hand reinforced`, `!testhamlet scoremenu native`, `!testhamlet ranking empty`, `!testhamlet uiprobe titleindex`, `!testhamlet uiprobe titlecontainer`, `!testhamlet uiprobe dutytitle`, `!testhamlet uiprobe titleform`, `!testhamlet uiprobe tutorialcontrol`, `!testhamlet uiprobe tutorialhamlet`, `!testhamlet uiprobe tutorialcombo`, `!testhamlet uiprobe tutorialclose`, `!testhamlet uiprobe scoreend`, `!testhamlet uidebug on|off`, `!testhamlet uiraw on|off`, `!testhamlet status`, `!testhamlet cancel`.

### 2026-08-10 title/HUD bootstrap correction

The title and live-HUD route is no longer an unknown widget-index problem.
Recovered Lua and installed cutscene assets prove this order:

1. `InstanceRaidBaseClass.startEvent` processes login/start data and plays the
   opening scene.
2. The scene's `2DEffectLocation8/9/10` marker opens
   `HamletDefenseTitleWidget1/2/3` in slot 14 through
   `SplashEffectWidget`.
3. `InstanceRaidHamletDefense.processStartEffect` prints the start NPC line and
   opens public effect `14/15/16`, which maps to
   `DutyCommencedWidget1/2/3` in slot 13.
4. After the base class waits another second, the subclass
   `openInformationWidget` opens `HamletDefenseWidget` in slot 15 and
   `HamletDefensePopupWidget` in slot 16.

The matching ending scenes contain `2DEffectDutySuccess1/2/3`. Manual
`widgetCreate` index `0x1B`, title-index, `_loadForm`, and widget-container
chains are therefore negative probes, not the retail path. The remaining live
gate is the native EventStart/UI-command lane attachment and its lifetime; see
`outputs/dungeon-widget-bootstrap-contract-20260810/`.
