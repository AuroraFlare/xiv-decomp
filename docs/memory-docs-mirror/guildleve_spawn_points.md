# Guildleve Spawn Point CSVs

Guildleve encounter POS exports are generated by:

```powershell
python tools\build_guildleve_spawn_points.py
```

Generated files:

- `tools/outputs/guildleves/spawn_points/guildleve_spawn_points.csv`
- `tools/outputs/guildleves/spawn_points/guildleve_spawn_points_all_sources.csv`
- `tools/outputs/guildleves/spawn_points/guildleve_spawn_point_summary.csv`
- `tools/outputs/guildleves/spawn_points/per_leve/*.csv`

The primary CSV prefers structured leve scripts first, then raw captured
`C:\serverdata\mobspawns_gl*.csv` rows for leves that are not scripted yet. It
still keeps captured `chest` rows for scripted leves because the script files do
not encode bonus chest locations. The all-sources CSV keeps both script and
capture rows for audit/comparison.

This is not yet a decoded client-DAT export. Treat `leve_script` and
`serverdata_capture` rows as recovered encounter data until each row is tied
back to a client-origin record.

Rows include:

- `leveId`, `title`
- `source`, `sourceFile`, `sourceLine`
- `zoneId`, `aetheryteId`, `aetheryteName`
- `wave`, `pointIndex`, `pointType`, `label`
- `mobIndex`, `mobId`, `mobName`, `objectiveIndex`
- `posX`, `posY`, `posZ`, `rot`, `groupId`

`pointType` can be:

- `mob`
- `circle`
- `chest`
- `run_path`

Current coverage from the local data is 470 primary points across 48
guildleves. The accepted capture rows include 41 `chest` points; suspicious or
unknown chest rows are ignored rather than guessed. All 48 currently recovered
guildleves have more than one encounter point, and 25 have more than one
`circle` marker point. For example, `12422` Crushing Chiglets has two circle
markers plus the associated mob and chest points.
