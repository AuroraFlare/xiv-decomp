# Pudding colours and elemental spells — 2026-09-12

The user requires every pudding added during mob placement to have a body
colour and spell list matching its element. The ordinary Plain Pudding profiles
1188 (original), 39304 (Copperbell), and 39424 (Mistbeard) previously had an
empty spell list. They share actor class 2103401, FlanNormalStandard.

`Map Server/Actors/Chara/Npc/BattleNpc.Pudding.cs` now supplies an elemental
fallback for ordinary m049 flans with no assigned spell list or director-owned
initial model state. It chooses one of six aspects on actor initialization,
retains it across respawns and command reloads, and configures its spell,
ranged attack element and same-element magic absorption together. The equal
six-way selection is authored variety, not a recovered retail distribution.
Recreating actors after a server restart may select different aspects.

| Element | Native model state | Body colour | Spell | Command ID |
| --- | ---: | --- | --- | ---: |
| Fire | 1 | Red/orange | Fire | 27310 |
| Ice | 2 | Pale blue | Blizzard | 27308 |
| Lightning | 3 | Purple | Thunder | 27313 |
| Wind | 4 | Green | Aero | 27353 |
| Earth | 5 | Yellow/gold | Stone | 27355 |
| Water | 6 | Blue | Water | 28957 |

The native state and colour evidence is
`outputs/flan-spirit-color-transition-decomp-20260831/17-flan-material-state-palette.csv`,
generated by `tools/build_flan_spirit_color_transition_decomp.py` from m049/e001
material animations. The model states are `init_msn001`–`006`, transitioning
from neutral using the native 15-frame/30-fps animation. `pur_mupt1`–`3` are
Magic Power Up effects and are not used as elemental colours.

The spell IDs and their Magic action types/properties are checked against
`Data/sql/server_battle_commands.sql`. The archive's Flan family record in
`docs/elemen-monster-archive/bestiary.json` describes colour-dependent spells
and absorption of magic of the same element. SQL `element=5` on Plain Pudding
is a crystal affinity, not a Fire ActionProperty or a native model-state ID.

Static world loading and dynamic spawns configure the fallback before actor
publication; OnSpawn provides an idempotent fallback for other spawn paths.
As requested on 2026-09-13, ordinary flans now send their selected colour in
the initial actor construction state. The neutral construction state and
one-second per-viewer colour commit have been removed for these actors. Late
viewers receive the same selected state immediately, and respawn refreshes
include SubState normally. Visibility does not select or replay a new aspect.

Toto-Rak's explicit Prison Pudding aspects remain director-owned: its existing
pre-add state and per-viewer delayed commit are preserved. Explicit calls to
`ConfigureElemenElementalProfile` now also pair m049 presentation with gameplay.
NMs and custom nonempty spell lists are excluded from random fallback and must
be authored explicitly. Existing family skills, profile IDs, placement IDs,
positions, levels, NM counts and drop lists are unchanged by this runtime fix.

Validation uses `Fishing Tests/PuddingElementTests.cs` via
`--pudding-elements-only`: all six canonical spell rows, colour ordinals,
ranged elements, absorption, rebind/reload persistence, custom/NM exclusions,
Toto-Rak presentation ownership, mismatched spell rejection, selected colour in
initial/repeated construction, and preservation of other substate fields.
These are server tests and native asset evidence,
not a new in-game visual confirmation.

Build to an isolated directory when the running Map Server holds the normal
Release DLLs open:

```powershell
dotnet build 'Fishing Tests/Fishing Tests.csproj' -c Release --no-restore -m:1 /p:UseSharedCompilation=false /p:OutDir=C:/Users/drime/source/repos/AuroraFlare/FF14-Memory/.codex-build/pudding-spawn-tests/ /v:quiet
dotnet '.codex-build/pudding-spawn-tests/Fishing Tests.dll' --pudding-elements-only
```

The running server is not replaced or restarted by this validation. Deploy
the rebuilt Map Server during the next normal server update to activate it;
no placement SQL migration or client DAT patch is required by this change.

Historical validation on 2026-09-12: the isolated Release build passed with zero
errors; `--pudding-elements-only` and `--totorak-leash-only` both passed. The
build reported NU1900 warnings because the NuGet vulnerability feed was
unreachable. No live database or running server was changed.

Validation on 2026-09-13 after the direct spawn change: the isolated Release
build passed with zero errors and nine existing warnings. The updated
`--pudding-elements-only`, `--totorak-leash-only` and
`--monster-presentation-only` suites passed. The selected state is verified in
server construction packets; its initial client rendering has not been tested
in game. No running server was replaced or restarted.
