## Push Rules

The full contract CSV carries both `required_runtime_args` from the argument atlas and `runtime_payload_args`, which folds in alias extra args, local exact examples, and route-owner extra-arg policy. Use `runtime_payload_args` when wiring a patch; use `required_runtime_args` when comparing back to the raw argument atlas.

Normal quest cutscenes should preserve the recovered delegate contract:

```lua
callClientFunction(player, "delegateEvent", player, quest, "processEventName", ...)
```

Do not join only by `scene_keys`. Scene keys such as `man30020` are payload, while the callable local method is the recovered delegate such as `pE20`. Case also matters: keys like `COM0l110` and `COM0L105` both appear.

For after-warp rows, keep the event open until the recovered method returns. Several recovered/local scripts call `player:EndEvent()` after the delegate; moving the end earlier is the kind of tiny change that makes a cutscene look fine and then strand the sequence.

SNPC payload rows need the five-value tuple in order before patching:

```lua
player:GetSNpcNickname(),
player:GetSNpcSkin(),
player:GetSNpcPersonality(),
player:GetSNpcCoordinate(),
player:GetInitialTown()
```

`snpc_tuple5_plus` means those five values plus another method-specific payload. It is not satisfied by the tuple alone.

Director rows are intentionally split out. They expect `noticeEvent` and event type `5`; examples include `man0g0`, `man0l0`, `man0u0`, and recovered director-only calls with blank quest code.
