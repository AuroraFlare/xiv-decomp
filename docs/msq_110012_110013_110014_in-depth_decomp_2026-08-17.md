### 1.2 Sequence flow

`SEQ_ACCEPT` is started from Momodi with `processEventMomodiStart`.

`SEQ_000` handles the initial Waking Sands handoff and route push into the minemite instance setup path.

`SEQ_010` is the battle leg start state.

`SEQ_015` sends the player to the Phrontistery private hallway and then to sickroom private space.

`SEQ_020` and `SEQ_025` are the sickroom/ritual movement handoff beats.

`SEQ_030` starts the Minfilia/Companion link-shell segment.

`SEQ_035` and `SEQ_040` step through Blackbrush/Arrzaneth transitions.

`SEQ_045` and `SEQ_055` resolve the final crypt/public-finish sequence and reward.

### 1.3 State progression details

`onTalk` in `SEQ_010` starts combat at Ascilia via `startMan2u0MinemiteDuty`.

The quest checks combat-eligibility with `checkCombatInstanceEntry` first.

The duty is launched by resolving zone `170`, private area `PrivateAreaMasterPast` type `5`, then creating director `Quest/QuestDirectorMan2u001`.

Combat flags and counters are:

- `MAN2U0_CNTR_MINEMITE_KILLS`
- `MAN2U0_FLAG_DUTY_ACTIVE`
- `MAN2U0_FLAG_DUTY_COMPLETE_PENDING`

onNotice completion for `SEQ_010` calls `finishMan2u0MinemiteDuty` when the completion-pending flag is set.

### 1.4 Duty internals (director)

- `MINEMITE_REQUIRED = 10`
- `MINEMITE_FIRST_SET_COUNT = 5`
- `MINEMITE_ACTIVE_CAP = 2`
- `FIGHT_LIMIT_MINUTES = 10`
- minemite template spawns = 5 base templates, reshuffled with replacement to 10 total spawns
- spawn IDs are assigned `man2u0_seq010_minemite_01` .. `..._10`

Director behavior includes:

- spawn-time helper allies (`Greinfarr`, `Niellefresne`) when enabled
- route movement for initial active minemites, then combat hold once at attack points
- kill count tracking from on-kill callback
- timeout/failure handling with cleanup and sequence reset
- completion completion trigger sent via `KickEventWithType` on Ascilia (`man2u0_seq010_ascilia`) with trigger name `noticeEvent` and event type `ETYPE_NOTICE`
- on success sets flag `MAN2U0_FLAG_DUTY_COMPLETE_PENDING`, updates ENPCs, and waits for client confirmation

### 1.5 Push/network transitions

`SEQ_010` Ascilia/Niellefresne/Fleh etc can be used as state gates.

`SEQ_025`, `SEQ_020` use fixed push object unique IDs for private area and exits.

Failure handling resets flags and returns back to `SEQ_010` with ENPC refresh.

### 1.6 Dialogue coverage

Core progression events are wired and playable.

Optional ambient lines exist in recovered scenario that are still not connected to server talk routes.

Known unbound ambient ranges from recovered `man2u0` include optional intro/echo/chase lines around `processEvent005_*`, `processEvent040_*`, and the `processEvent070_2` variant.

### 1.7 Rewards

Completion path in `SEQ_055` does:

- `sqrwa` reward UI
- `CompleteQuest`
- `AddItem(1000001, 30000)`
- `AddExp(50000, playerCurrentClass, 0)`

### 3.4 Director mechanics (`QuestDirectorMan20610`)

`main` uses three hard-coded route legs:

- inbound route: `together_we_stand_inbound`
- post-duty route: `together_we_stand_post_cs`
- return route: `together_we_stand_return`

Route completion is synchronized through `noticeEvent` (`"legComplete"`) to avoid direct delegate calls from timer-only code without an active event owner.

Inbound completion triggers `processEvent016`.

Post-CS completion transitions to podling pickup state and triggers:

- `pE20`
- podling status `Intact-Podling Toting` (`223993`)
- `SEQ_025`

Return completion triggers:

- `pE30`
- podling status clear
- `SEQ_030`
- content/route teardown and private-to-public warp out

Failure paths reset to `SEQ_015`, clear podling status, and re-open rendezvous route.
