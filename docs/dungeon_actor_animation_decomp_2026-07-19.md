## Decisive result: the packed middle value

The animation ID is an 8/12/12-bit packed value. `FUN_0045c940` constructs `(middle & 0xFFF) << 12 | category << 24 | low & 0xFFF`; `FUN_0045c2d0` looks up the base resource with `((id >> 12) & 0xFFF) << 12 | id & 0xFF000000`. Thus bits 23..12—the **packed middle value**—select the base action bank, and its **decimal** value becomes the zero-padded four-digit filename. The low 12 bits are called `effect` by `gm/anim.lua`, but native base-bank lookup discards them; finer low-field semantics are not established here.

This fixes the important constants:

- `0x040C9000`: category 4, packed middle value **201**, low 0 -> `base/0201`.
- `0x0405E000`: category 4, packed middle value **94**, low 0 -> `base/0094`.
- `0x04004000`: category 4, packed middle value **4**, low 0 -> `base/0004`.
- `0x04000201` does **not** mean bank 201; it has middle 0 and low 513.
- `0x04000094` does **not** mean bank 94; it has middle 0 and low 148.
- `0x04004004` finds bank 4, but the extra low 4 is not required for that lookup and is not proven to request an independent second effect.

The unrelated `AnimaTreasureBox` control confirms the join: `0x041FC000` has middle 508 and resolves to installed player bank `0508` (`cbfm_sukumu`), whereas `0x04000038` has middle 0/low 56 and finds no installed base bank.

## Toto-Rak terminal / barrier

The reconstructed two field devices and three boss-activation terminals use
actor **1200202**, appearance **b936/e003**. Its model payload embeds the
persistent `b936_e03v1` effect. The decoded `@CBIS` graph has complementary
conditions on `extrastat` mask `0x80`: set enters the effect block and clear
enters the kill block. A live `!spawnbgmodel b936 e003 - 0x80` test confirmed
the broad blue floor sigil and perimeter flames. Runtime interactive terminals
retain bit `0x01`, use `0x81` while powered, and send opcode `0x145` before
appearance initialization.

Current-local actor **1200228** is `/Chara/Npc/Object/RaidDungeonBarrier`, appearance base **20936**, body **4096**, therefore **b936/e004**. Its model binary embeds v1 resource `b936e04v1`; action bank `b936/0004` separately binds `b936e004`, embeds v2 `b936e04v2`, and contains Action/BindActor/Effect/Sound clips but no skeletal motion. That makes **`0x04004000` an asset-derived direct-bank test candidate**, not a recovered retail caller.

The exact recovered Lua caller is `RaidDungeonWarp.activateWarpDevice`, which sends decimal 67493888 = **0x0405E000**. Its packed middle value 94 selects the unique installed chara bank `b936/0094`, which binds b936/e004, `initf_idle`, and `RaptureCancelChantSyncClip`. This proves an e004 10 ms control/cancel transition on warp activation. It does **not** prove a Toto-Rak inactive state.

This e004 caller is the separate exit-transporter activation path: replay
`rad0f307` labels actor `1200203 / e004` as `GOAL`. It is not the persistent state of the e003 photocell/activation consoles.

`b936/0004` is 55,040 bytes, SHA-256 `4a12fc6f6076b919cf008c9f14a0215ed4b7774aee49b8fc43cc1c62b7dd48fa`. Its exact parsed active block is 560000 units with 3 entries; **~0.56 s assumes the integer field is microseconds**. The aligned 530000 values are candidate timing words/markers found by a repeatable heuristic, not proven authored timestamps. `b936/0094` is 1,232 bytes, SHA-256 `ba71a7d66808704200a99eb508d306e8fae2ffe5fdd98bc4135f8f8f0dd74cd0`, with an exact 10000-unit active block and 2 entries (~0.01 s under the same unit inference).

The two small e004 controls make the family pattern explicit. `0014` and `0094` are both 1,232-byte b936/e004 bundles with `initf_idle`, `BindActorClip`, and `RaptureCancelChantSyncClip`; a byte-for-byte comparison differs at only four byte positions, including one ClipGid byte. `0014` (SHA-256 `3af9353f36d0585d09e115a6965764321a0178962c4b17fe07731caa4984c414`) uses an exact 560000-unit block matching full bank 0004, while `0094` (SHA-256 `ba71a7d66808704200a99eb508d306e8fae2ffe5fdd98bc4135f8f8f0dd74cd0`) uses 10000 units. This supports “duration-matched control” versus “immediate control/transition,” not named active/inactive states.

## How coffers animate

Actor **1200161** is exactly the retail `/Chara/Npc/Object/GuildleveBonusTreasureBox` with b923/e003 appearance; this server currently reuses it as a shared content coffer. That does not prove the original retail dungeon coffer actor.

Live client validation on 2026-07-19 established the current-local pairing: direct scheduler **0x04001000** selects b923 bank `0001` and visibly opens actor 1200161. Direct **0x040C9000** produced no visible action on the same actor. The runtime therefore uses bank `0001` for its current GuildleveBonusTreasureBox while retaining `0x040C9000` below only as exact recovered `RaidDungeonTreasureBox` evidence.

`RaidDungeonTreasureBox.processOpenDzemaelEpicQuestType` always finishes with **0x040C9000**: category 4, packed middle value **201**, low 0, therefore decimal bank `0201`. `b923/0201` is 98,560 bytes, SHA-256 `717a21c682c7880c1f0af59f0b6f6336edb119e83db375c6a9e7b651265c4c95`, with an exact 8-entry/2100000-unit active block (~2.1 s under the microsecond inference) and motions `cbmm_mp_act1` plus `cbmm_mp_act2`.

The bank is family-level and does **not** name e003. Bank 201 distinguishes the two-motion b923 presentation from b923's one-motion banks, not an appearance variant.

### Why client assets alone cannot reconstruct the class join

The actor protocol separates the numeric appearance key from the script class name. Current `Npc.cs:104` calls `LoadNpcAppearance(actorClass.actorClassId)`, while `Npc.cs:108-109` derives the class name from the server-side `classPath`. `ActorInstantiatePacket.cs:50-51` then writes that class name into the instantiate payload at offset **0x24**. Therefore a retail actor-instantiation capture containing both the actor class ID and transmitted class name could close the gap; the b923 model/action bundle by itself cannot.
