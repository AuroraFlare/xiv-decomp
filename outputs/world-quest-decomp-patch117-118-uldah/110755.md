## Edge-case notes

- Accept-path loophole FIXED in this pass: offer branch used `not player:HasQuest(quest)` while siblings use `seq == SEQ_ACCEPT`. After completion the quest leaves the journal, so `HasQuest` is false and a completed player re-talking to Mumukiya replayed the offer cutscene before `AcceptQuest` (correctly) refused via `CanAcceptQuest`. Changed to `seq == SEQ_ACCEPT` for consistency; behavior for eligible players is identical (SEQ_ACCEPT is the only state where the offer NPC carries QFLAG_TALK).
- No counters; nothing to reset on abandon/re-accept (engine allocates fresh `QuestData` regardless — VERIFIED `Quest.cs:349-356`).
- Death/disconnect: no volatile state. Safe.
- `CompleteQuest` exactly once (single SEQ_001 Mumukiya branch). No double-claim.
- `UpdateENPCs` + `EndEvent` on all non-accept paths; accept path ends event after accept. Wrong-NPC talks are no-ops.
